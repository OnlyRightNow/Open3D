# Open3D issue triage against 0.20.0

Scope: open upstream bug reports (isl-org/Open3D) about geometry, registration and the Tensor core, most recently updated first.
Issues triaged: 129 (fewer than the 150 cap qualified in the searches run).
Tested with `open3d-cpu==0.20.0` (Python 3.13, Linux x86_64, no GPU, no display). Every FIXED and CONFIRMED verdict comes from a script that was run here; scripts are in `repros/<issue>.py` and print `OK:` or `BUG REPRODUCED:`.

## Method and limits

- The gh token in this environment is invalid and api.github.com is blocked, so issues were read from github.com HTML pages (read only). Nothing was posted.
- The issue list came from the `label:bug` search sorted by update (all 12 pages) plus keyword searches; order is approximate.
- CUDA, SYCL, Windows, macOS, aarch64 and GUI paths could not be tested; those issues are CANNOT TEST HERE.
- Some FIXED or NEEDS INFO rows are really "not a bug" (the evidence column says so). The five categories have no separate slot for that.
- Where the reporter's data was not available, the verdict uses synthetic data and says so.

## Source build notes

The build used CPU only, `BUILD_GUI=OFF`, `BUILD_WEBRTC=OFF`, `BUILD_ISPC_MODULE=OFF`, `WITH_IPP=OFF`. Release-asset downloads were blocked by the network policy, so several dependencies came from the system (BLAS, curl, OpenSSL, zstd, msgpack, ZeroMQ, VTK 9.1, Eigen 3.4, libpng, googletest) and assimp 6.0.5 was built from its git tag. GitHub source archives were rebuilt from git with `git archive | gzip -n`, which reproduces the pinned SHA256 hashes. None of this touched the repository.

- With `BUILD_GUI=OFF`, the `python-package` target fails in stub generation (pybind11-stubgen 2.5 cannot parse `open3d::visualization::rendering::TriangleMeshModel` and `MaterialRecord` default arguments). `-DIGNORE_STUBGEN_ERRORS=ON` works around it.
