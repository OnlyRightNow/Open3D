## Motivation and Context

`VoxelGrid.create_from_point_cloud_within_bounds` ignores `max_bound` (it is only used for an overflow check) and voxelizes every point. Points outside the requested bounds create voxels with negative or too-large grid indices, e.g. `[22, 22, 22]` or `[-10, 2, 2]` for a grid that should span indices 0..4.

## Description

**Plan summary**
- Goal: voxelize only points inside `[min_bound, max_bound]`, as the name and docs say.
- Requirements: bounds are inclusive on both sides (same as `AxisAlignedBoundingBox`); NaN points are skipped; `create_from_point_cloud` (which calls this function with the cloud bounds padded by half a voxel) still keeps every point; no API change.
- Test method: new C++ test `VoxelGrid.CreateFromPointCloudWithinBounds`, new Python tests in `python/test/geometry/test_voxel_grid.py`, plus the triage repro script.
- Risk: users who relied on out-of-bounds voxels lose them. That output contradicted the documented contract, so a CHANGELOG entry is added.

**Root cause**
`cpp/open3d/geometry/VoxelGridFactory.cpp`, `VoxelGrid::CreateFromPointCloudWithinBounds`: the point loop computes a voxel index for every point and never checks it against the bounds.

**Change**
- Skip points outside the bounds in that loop (4 lines).
- Doxygen in `VoxelGrid.h` and the pybind docstring now say out-of-bounds points are skipped.
- CHANGELOG entry.
