## Motivation and Context

`PointCloud.create_from_rgbd_image` with a 4-channel (RGBA) color image puts alpha into the blue channel: pixel (10, 100, 200, 255) becomes color (10, 100, 255). The issue was marked as a duplicate of #1086, but #1086 is the feature request for per-point transparency; this one is a wrong-color bug.

## Description

**Plan summary**
- Goal: for RGBA color, use channels 0, 1, 2 and ignore alpha.
- Requirements: 3-channel and 1-channel output stays bit for bit the same; no change to scaling, supported formats or NaN handling.
- Test method: new C++ test `PointCloud.CreateFromRGBDImageColorChannels` (3, 4 and 1 channel), new Python tests in `python/test/geometry/test_pointcloud_rgbd.py`, existing `PointCloud.CreateFromRGBDImage`, plus the triage repro.
- Risk: none expected beyond the intended change; the 1 and 3 channel indices are unchanged by construction.

**Root cause**
`cpp/open3d/geometry/PointCloudFactory.cpp`, `CreatePointCloudFromRGBDImageT<TC, NC>` reads `pc[0], pc[(NC - 1) / 2], pc[NC - 1]`. That is (0, 0, 0) for NC=1 and (0, 1, 2) for NC=3, but (0, 1, 3) for NC=4, so blue is replaced by alpha.

**Change**
Use explicit G and B offsets (`constexpr`, 1 and 2 for NC >= 3, 0 for NC = 1). Doxygen of `CreateFromRGBDImage` now lists the accepted color formats.
