## Motivation and Context

With a `VoxelBlockGrid` that has no `color` attribute (the default in the reconstruction example), `extract_point_cloud` and `extract_triangle_mesh` throw `Tensor has shape {0}, but is expected to have compatible with {None, 3}` when nothing passes the weight threshold, for example after integrating fewer than 3 frames. In C++ this exception is uncaught and aborts the program, which matches the report.

## Description

**Plan summary**
- Goal: an empty extraction from a grid without colors returns empty geometry instead of throwing.
- Requirements: with a `color` attribute, behavior is unchanged (including the empty case); non-empty extraction without color still has no colors; kernels and signatures unchanged.
- Test method: new C++ test `VoxelBlockGridPermuteDevices.ExtractEmptyWithoutColor` and Python test on a synthetic depth image (no dataset download), the existing `VoxelBlockGrid` tests (their golden point, vertex and triangle counts still match), plus the triage repro.
- Risk: low. Only host code after the kernel call changes.

**Root cause**
`cpp/open3d/t/geometry/VoxelBlockGrid.cpp`, `ExtractPointCloud` and `ExtractTriangleMesh` decide whether to set colors with `colors.GetLength() == normals.GetLength()`. The kernels only allocate colors when the grid has a `color` attribute; otherwise the tensor has shape `{0}`. When 0 points are extracted the lengths are both 0, so `SetPointColors` / `SetVertexColors` is called with a `{0}` tensor and throws.

**Change**
Check `block_value_map.Contains("color")`, the same condition the kernels use, in both functions. When colors exist they always have the same length as normals or vertices, so every non-empty case behaves as before. Doxygen notes the empty result and when colors are included.
