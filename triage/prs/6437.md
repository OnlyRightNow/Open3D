## Motivation and Context

PCL marks padding bytes with fields named `_`. `o3d.t.io.read_point_cloud` crashes (heap corruption, abort or segfault) on PCD files with two or more such fields, which are common in files written by PCL and ROS. A maintainer asked for a PR that ignores `_` fields as PCL does. The legacy reader already handles these files.

## Description

**Plan summary**
- Goal: the tensor PCD reader skips `_` padding fields instead of crashing.
- Requirements: no `_` attribute is created; padding is skipped in ascii, binary and binary_compressed data; every other field keeps correct values wherever the padding sits; files without `_` fields are unchanged; no API change.
- Test method: new C++ test `TPointCloudIO.ReadPCDWithPaddingFields` and Python test `test_t_read_pcd_with_padding_fields` (ascii and binary), plus the 2M-point triage repro.
- Risk: an attribute literally named `_` is no longer loaded. That never worked (it crashed), and PCL defines `_` as padding.

**Root cause**
`cpp/open3d/t/io/file_format/FilePCD.cpp`:
1. `InitializeHeader` registers every non-standard field, including each `_`, as an attribute.
2. `ReadPCDData` then calls `SetPointAttr("_", ...)` again for every `_` field, which frees the previous tensor, while `map_field_to_attr_ptr.emplace("_", ...)` keeps the pointer to the first, freed buffer. The read loops then write through that dangling pointer.

**Change**
Drop `_` fields from `header.fields` in `InitializeHeader`, after the header is fully parsed. Each remaining field keeps its stored byte offset and ascii column offset, and the record size and column count are computed before this point, so all three data formats still address the right bytes.
